# Repository Guidelines

## Architecture

Poker Bank is a Rust HTTP/WebSocket server with a strict TypeScript browser client. `src/` owns authoritative rules, typed state, SQLite transactions, credentials, QR generation, and backups. `web/` owns browser code and validated wire schemas. `public/app.js` is generated by `npm run build`; never edit it manually. `tests/` contains Rust regression tests; `test/` contains TypeScript integration tests. Deployment files live in `deploy/` and `.github/workflows/`.

## Required checks

Follow [CONTRIBUTING.md](CONTRIBUTING.md). Before submitting, run `npm ci`, `npm run format:check`, `npm run lint`, `npm run build`, `cargo fmt --all --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked`, `cargo build --locked`, and `npm run test:integration`. Use Node 24 and stable Rust. Never weaken strictness flags or suppress failures to pass CI.

## Changes and testing

Rust owns all game decisions. Validate untrusted messages at both boundaries. No `any`, unchecked non-null assertions, `@ts-ignore`, or unsafe Rust. Poker changes require regression tests and chip conservation. Preserve saved SQLite data, existing seats, command deduplication, and wire compatibility. Gameplay undo must never erase cash transactions. Test UI changes on phone and desktop.

## Contributions and deployment

Use focused branches and imperative Conventional Commits. Pull requests need a concrete description, validation evidence, and screenshots for UI changes. Main builds deploy automatically after CI passes; document migrations and rollback implications. Never commit databases, seat tokens, private keys, or provider credentials. Commit inside this project’s isolated repository, never the surrounding Notes repository. Keep unrelated homeserver services and shared proxy configuration outside application changes.
